# The grilling of 2026-11-10: answers

The owner answered one question at a time. Facts that could be looked up
were looked up and are marked **fact**. Everything else is the owner's
answer, marked **owner**.

## Round 0: facts

- **Q1, how services start, and the deploy gate (fact).** pm2 is gone.
  Every service runs in a container built from its repo's
  `infrastructure/Dockerfile`, and the container starts a file path, for
  example `CMD ["node", "server/dist/index.js"]`. The build runs `npm ci` and
  `npx tsc -b <package>`, and no tests or lint. So renaming `index.ts` to
  `server.ts` must change the Dockerfile's `CMD` in the same commit, and the
  repo owns that file. Brief 15's default ("add lint to the deploy only if it
  already runs tests or lint") resolves to: leave the deploy alone.
- **Q2, private repos (fact).** No private repo uses Base UI. Fastify is used
  only by dwh-finance (Fastify 5.8.5 and zod 4.4.3, a finished second-semester
  university project). educational-platform has no JavaScript project.
  theme-200177-j5 is a PHP template, and master-thesis-research has no web
  app.
- **Q3, Open Library (fact).** It answers from the owner's machine (HTTP 200
  on 2026-11-10), so Shelfmark 04's step 1 runs locally.
- **Q4, PRs (owner, 2026-11-10).** The owner merged every cloud PR. From now
  on there are no PRs: work happens on `main` in each repo's main checkout,
  committed and pushed directly.
- **Q32, a second reviewer (fact).** Neither the Codex nor the Gemini CLI is
  installed, so brief 22 is parked.

## The owner's answers

- **Q19, visual parity (owner): close enough.** A Tailwind migration is done
  when before and after screenshots at 1280 and 390 px show no visible change
  to layout or colour. Drift of a few pixels in spacing or rounding needn't
  be fixed or listed. Changes: brief 02's acceptance and every repo's Tailwind
  brief.
- **Q18, dark mode (owner): a switch everywhere, light by default.** Every
  app gets a Light / Dark / System choice, as Postern has, and a first visit
  shows the light theme rather than following the system. The choice is kept
  where the app keeps its other settings: on the device by default, and
  atrium keeps its per-profile sync (and its sepia theme).
  Tailwind's `dark:` variant keys off a `data-theme` attribute through
  `@custom-variant` (Postern's method), not `prefers-color-scheme`. Changes:
  brief 02 (a theme rule), and every repo's Tailwind or Base UI brief gains a
  theme-switch step.
- **Q40, the phone menu (owner): the swipeable Drawer.** Phone navigation
  panels move to Base UI 1.9.0's `Drawer`, closed by a swipe as well as a tap
  outside, the X or Esc. Changes: brief 02 (a rule for phone navigation) and
  Almanac's Base UI brief; any repo with a phone menu panel.
- **Q58, confirms (owner): keep inline.** "Delete? Yes / No" in place stays
  the pattern in Satchel and Shelfmark. No move to `AlertDialog`.
- **Q58, form dialogs (owner): stay open on an outside tap.** A dialog that
  holds a form sets `disablePointerDismissal`. It closes with Cancel, the X or
  Esc. Changes: brief 02 (a rule) and each repo's Base UI audit.
- **Q36, Shelfmark recommendations (owner).** The third place is
  **Wishlist**, and recommendations are part of it. The wishlist moves out of
  Library into this place, and it has an **Add a book** button for books the
  owner hears about. Where the picks come from:
  1. a free recommendation service, or a small model Shelfmark can run itself,
     if one is good enough;
  2. otherwise Claude, by hand: the page offers a download of the library (CSV
     or the database) with a ready prompt, and an **Import** button that takes
     the JSON Claude returns.

  Research on 2026-11-10 found TasteDive, a free key at about 300 requests an
  hour with a books category. It is a legacy API since TasteDive joined Qloo,
  and is kept "until full migration". Hardcover's GraphQL API has no
  similar-books query, and its own recommendations are only planned. A small
  sentence-embedding model (all-MiniLM-L6-v2, about 23 MB, run in Node through
  transformers.js) could rank Open Library candidates by the owner's subjects
  and descriptions. Shelfmark 04's first step tries TasteDive and the
  embedding ranker on the real library. If neither gives useful picks, the
  export, prompt and import path ships on its own. Refresh stays on a press,
  and a book already owned, wished for or dismissed is never shown. Changes:
  Shelfmark 04 (rewritten around Wishlist) and Shelfmark's "Two places only"
  decision (revisited: three places, Library, Add a book and Wishlist).
- **Q37, Newspapper video (owner): not yet.** No Reels support for now.
  Newspapper 06 moves to `briefs/blocked/`, blocked by "the owner asks for
  video export".
