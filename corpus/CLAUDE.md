# my-personal-skills corpus: rules

This directory is the project's wiki and work tracker, kept by the LLM. The
owner curates sources and asks questions. The LLM writes the synthesis and
tracks the work. Anything worth keeping from a chat goes back in here.

The repo is public. Write for a stranger reading it on GitHub: no secrets, no
machine paths, no domain, no personal details.

## Layout

```
corpus/
  CLAUDE.md    this file
  index.md     catalog, generated by `bash corpus/lint.sh --index`
  routing.md   which skill runs the work, which layer answers which question
  lint.sh      health check; exits non-zero on failure
  log.md       chronological record, newest last
  todos/       captured ideas, as prose, before they are specs
    blocked/   todos that wait on an outside condition
  briefs/      numbered work specs
    todo/  blocked/  done/  superseded/
  wiki/        the synthesis pages
```

## Retrieval budget

1. Read `index.md` first and triage on the `summary:` lines.
2. Open at most 2-3 wiki pages. Needing a fourth means a page straddles two
   topics or a summary is vague. Fix that instead of reading more.
3. Don't read `briefs/` or `todos/` wholesale. `wiki/status.md` has the
   snapshot. Open a brief only for the spec behind a specific piece of work.
4. To answer "what's blocked", list the two `blocked/` folders and run
   `grep -rh "Blocked by\|blocked-by" corpus/`.

## Frontmatter

Every page in `wiki/` opens with exactly two keys:

```
---
summary: <what question this page answers, written for an agent deciding whether to open it>
updated: <YYYY-MM-DD>
---
```

`index.md` is generated from the summaries. Never edit the catalog by hand.

## Briefs

- A todo becomes a brief at `briefs/todo/<NN>-<slug>.md`. NN is the max across
  all four brief folders (`todo/`, `blocked/`, `done/`, `superseded/`) plus
  one, two digits. Numbering never restarts.
- Finished work moves from `todo/` to `done/` with the same number and a short
  outcome note added at move time. After that the file is immutable.
- Work later undone moves to `superseded/` with a one-line note on top. Never
  renumber, never rewrite a done brief.
- Work that waits on something outside the work lives in a `blocked/` folder:
  a brief in `briefs/blocked/` with `**Blocked by:** <condition>` right under
  its H1, a todo in `todos/blocked/` with a `blocked-by: <condition>` key in
  its frontmatter. The condition is one short line someone can check. To
  unblock, `git mv` the file back (to `briefs/todo/`, or to `todos/`) and
  remove the line. A blocked brief reaches `done/` only by way of `todo/`.
  Never start a blocked brief; the owner says when it moves.
  This is separate from brief-board's Blocked status.

## Source of truth, when things disagree

1. The skill files win over any wiki claim. Verify a path or section before
   acting on what a page says about it.
2. A brief in `done/` wins over the wiki until the wiki catches up.
3. `wiki/decisions.md` wins over `wiki/status.md` for choices nobody has
   formally revisited. Changing a recorded decision needs an explicit revisit
   and a `log.md` entry.

## Skill changes

- Every change to a skill bumps the plugin version in
  `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` (both
  places in the marketplace file), updates the version line in `README.md` and
  adds a paragraph to `docs/history.md`. The commit message ends with the
  version: `feat(corpus-flow): blocked briefs and todos -> v0.34.0`.
- Skills ship when the owner updates the plugin. Nothing here is deployed.
- Skill and doc text is plain, direct English. Other repos are named, never
  pathed. No domain, local paths or usernames.

## Writing

- Standard relative markdown links. Absolute dates only.
- One concept per page. Split a page past 200 body lines.

## Hard rules

- **No secrets** in the corpus or the repo.
- **No CI.** Don't add GitHub Actions, runners or other GitHub-specific
  automation.
- **No pushes.** Commit locally. The owner pushes.

## brief-board

Brief progress goes on brief-board. Run `brief-board guide` before you start
or resume a brief, and follow it. Until the owner's first sync puts this repo
on the board, skip the board and say so in the hand-back.
