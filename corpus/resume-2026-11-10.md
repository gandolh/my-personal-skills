## How to write a repo's briefs (the method that worked)

For each repo, dispatch one `general-purpose` subagent on Sonnet. The
reference is Almanac's four briefs, in Almanac's
`corpus/briefs/todo/01-…04-…`.

**Copy their shape:**

- `# Task NN`, **Depends on**, **Runs before**, **Before you start**, then
  Context, Owner decisions (defaults), Files you OWN, Files you must NOT
  touch, What to do, Acceptance, Interplay;
- dated measurements, each with its command;
- `file:line` for every count;
- code paths in backticks;
- one commit per step;
- every acceptance item a command or a test.

**What each brief covers:**

1. **The Base UI 1.9.0 bump**, only if a pin or the lockfile isn't exactly
   1.9.0. It comes first and has no dependencies.
2. **The house-style harness:** Prettier churn by width, the tsconfig flags,
   the ESLint diff with the typed rules, `check`/`check:fast`,
   `.claude/rules/`, a root `CLAUDE.md`, and the house-shape counts.
3. **Base UI by the conventions:** the audit against rules 1-13 with
   `file:line`, and the wrapper set. For a repo without Base UI, it is an
   adoption.
4. **The web app to Tailwind**, for plain CSS or CSS Modules only.
5. **The server in the code structure**, for Fastify only: a move map, the
   env readers, every route and its schemas, the error plugin, the entry
   rename, and zod 4 where the repo resolves 3.

**Rules for the agents:**

- Follow the repo's own corpus conventions: numbering never restarts, so
  check `log.md` for a reset.
- Research is read-only.
- Measure on a scratch copy.
- Name the skills library's briefs by title, never by path.
- Run `bash corpus/lint.sh` until it ends clean.
- Don't commit. The controller commits and pushes to the repo's one PR.
- Give each agent the facts on the Round 8 page.

**Usage.** Each agent spends about 250-450k tokens. Five or more at once
hit the account's five-hour limit three times on 2026-11-10, so run **at
most 3 at once**.
